活版印刷的字有一種螢幕上很少見的樣子。邊緣不齊，墨色不勻，偶爾缺一角。那些都不是設計，是金屬、油墨跟紙互相妥協之後剩下的東西。

最偷懶的做法是拿張掃描的圖來貼。但那樣字就不是字了 —— 不能選取、不能複製、搜尋不到、螢幕閱讀器也讀不到，換一句話還得重掃一次。所以只能用 CSS 加 SVG 濾鏡，讓它仍然是一段真的文字，只是長得像被壓過。

那就得先問：鉛字壓在紙上，到底發生了什麼事？

## 一、紙

沒有紙就沒有活版。而紙不是白色的平面。

抄紙的時候纖維會有方向性，所以紙面有很細的橫紋直紋；曝光不均，整張紙中間跟邊緣的明度不一樣；再加上纖維本身的顆粒。這三層疊起來，白紙才會像紙。

```widget
{ "name": "letterpress-press", "only": "paper" }
```

實作上有個地方卡了一陣子：**噪點必須蓋在字的上面**，不是下面。墨壓在紙上，紙的顆粒是透過墨看到的，所以那層得用 `multiply` 疊在文字之上。但 CSS 的 `background` 永遠在內容後面，做不到。

最後是用 `::before` 跟 `::after` —— 剛好兩個，一個放字下面的纖維與曝光，一個放字上面的顆粒。整張紙不需要任何額外元素，`<div class="lp lp-paper">` 就有了。

## 二、墨

油墨會滲進纖維，所以筆畫的邊緣不是刀切的，是暈開的。墨上多了字會胖一圈，小字的字腔還會被填掉。

```widget
{ "name": "letterpress-press", "only": "ink" }
```

這道用 `feConvolveMatrix`：一個固定係數的高斯核心把 alpha 往外暈一圈，後面再用 `feComponentTransfer` 決定那一圈有多少變成實心。

暈開的寬度由核心大小決定，3×3 就是一像素，5×5 是兩像素。所以「能胖到多胖」有個上限，不是把參數調大就會一直胖下去 —— 這件事我是一路把數字往上加、發現畫面完全不動，才想通的。

## 三、壓

壓力不夠，紙跟字面接觸不完全，印出來會有整塊沒沾到的空白。壓太重，墨被擠到字的外圍。

有個我原本沒想到的：**壓力愈大，筆畫被推歪的程度反而愈小**。因為壓力會把紙面壓平，纖維的起伏就不再頂開筆畫。所以輕壓的手刷本，字比機器印的更歪。

```widget
{ "name": "letterpress-press", "only": "pressure", "text": "活版印刷" }
```

## 四、字

鉛字會磨損。這裡我一開始做錯了：以為「舊字」就是缺角變多，所以只調缺角的比例，結果滑桿從頭拉到尾幾乎看不出差別。

後來才想通，新字跟舊字的缺陷不是同一種東西。新字是鑄造時表面的細微瑕疵，一點一點的；舊字是真的崩掉一角。所以年紀變大不只是缺角變多，**單個缺口的尺度也要跟著變大**。兩個一起動，才終於像用久的字。

```widget
{ "name": "letterpress-press", "only": "wear" }
```

## 五、一支濾鏡不夠

到這裡四個成因都調好了，看起來挺像樣。然後我把字級放大，整個垮掉。

原因是噪點的週期是**絕對長度**，不會跟著字級縮放。同一組參數，在 16px 的內文上是恰到好處的斑駁，放到 60px 就變成整塊筆畫被剪掉，字直接散架。

```widget
{ "name": "letterpress-press", "only": "size", "text": "見本" }
```

所以大字不能用同一招。內文級數靠的是「挖」，拿噪點當遮罩把零星像素挖掉；大字改成「調密度」，低頻噪點乘進 alpha，筆畫的結構完整保留，只是有的地方吃墨飽、有的地方虛，像印章蓋不勻。

這也是為什麼最後是四支濾鏡而不是一支：內文小字、一般行文、標題、大字，各有各的參數。而既然幾號字該配哪支是固定的，那就讓字號的 class 同時決定字級跟濾鏡，不要留給人自己記。

## 六、排字

前面講的都是整段一起發生的事。但鉛字是一顆一顆撿出來排進版盤的，所以每顆字的狀態其實不一樣 —— 位置差那麼一點，沾的墨也有多有少。

```widget
{ "name": "letterpress-press", "only": "set" }
```

這件事沒辦法用純 CSS 做，因為 CSS 碰不到單一字元。`::first-letter` 只能吃第一個字，`::nth-letter()` 提了十幾年，至今沒有任何瀏覽器實作。所以只能把每個字包成自己的 `<span>`。不過拆字可以在建置期或伺服器端做完，瀏覽器端仍然不用跑任何 JS。

包好之後，歪斜跟濃淡就都是純 CSS 了。這裡不能用亂數 —— 伺服器端跟瀏覽器端得算出同一個結果，不然畫面會閃一下。所以用的是好幾個互質的週期疊在一起：`nth-child(11n+6)`、`nth-child(13n+8)`、`nth-child(17n+3)`、`nth-child(23n+11)`⋯⋯ 週期挑大的，整段讀下來才看不出循環。

代價是短樣字幾乎看不出效果。上面那段如果只有七個字，四條規則裡只會命中兩條，而且視覺最強的那兩條剛好輪不到。所以這一節的示範非得是一整句不可。

## 附：自己玩玩看

四個成因加上字級，湊在一起。幾組預設是常見的印壞情況。

底下印的是實際算出來的濾鏡參數。一個成因會同時牽動好幾道 —— 那個對應關係其實才是整套東西的核心，剩下的都是實作。

```widget
{ "name": "letterpress-press" }
```

## 七、然後 Safari 給了一腳

做到一半發現 Safari 上整片字糊成一坨，缺角跟濃淡全部不見。

追下去，兇手是一道 `feGaussianBlur`，`stdDeviation` 只有 0.28。次像素的模糊，WebKit 走規格書那套三次 box blur 近似、box 寬取整數，Skia 在小 σ 走真高斯 —— 兩邊算出來的東西本來就不一樣。

但真正反直覺的是：**單獨看那道模糊，兩個瀏覽器幾乎沒有差別**。我一開始就是這樣被騙過去的。問題在後面緊接著一道把 alpha 拉硬的運算，那點微小的誤差被斜率放大，就成了整片筆畫脹開黏死。單一變因看不出來，組合起來才爆炸。

後來把模糊換成固定係數的卷積核 —— 規格把數字寫死，引擎沒有近似的餘地，兩邊逐像素相同。順帶也發現 `feMorphology` 有類似的毛病：它的半徑會被取整到整數裝置像素，滑桿推到 0.24 沒事、0.27 突然粗一圈，而且跳階的位置跟螢幕的 DPI 綁定，換台機器就跑到別的地方。

整理起來大概是這樣：SVG 濾鏡裡凡是**空間性**的運算 —— 模糊、侵蝕、膨脹 —— 在次像素尺度不是引擎分歧就是量化。逐像素的查表運算則從頭到尾沒出過事。真要調到這種精度，就別把質感押在前者上。
